## 症状

移行計画 Phase 2 の並走（新経路＝エージェントが画面を操作してから撮る）で、
**初の観測**を取った結果。エージェントは4往復・$1.89（上限$2.00）を使い切り、
**目標の状態を作れなかった**。

記事が求めた状態: 分類する項目=「品番」/ 集計方法=「合計」/ 対象=「符号付き数量」
撮れた画像: 分類する項目=「区分」/ 集計方法=「レコード数」のまま

## 判断は正しかった

思考ログを読むと、エージェントは**毎ターン正しく考えていた**。

- [0]「分類する項目を『品番』に、集計方法を『合計』に変更する。合計を選ぶと
  対象フィールドの選択欄が新たに表示されるはずなので、次のターンでそこに設定する」
- [1]「『大項目』はボタン型の選択メニューで、**set では値を変更できない**ことが
  前回の結果から分かっている（クリックしてもメニューが開くだけ）」
- [2]「直前のクリックでフィールド選択パネルが開いた（DOM末尾に検索欄が出現）。
  検索欄に『品番』と入力して候補を絞り込む」
- [3]「候補がまだ要素一覧に現れていない。パネルを閉じて状態を失うリスクを避け、
  今回はそのままにして集計方法を開く」

最後のスクショでは**集計方法のメニューが開き「合計」が画面に見えている**。
あと1クリックだった。

## 根本原因

**失敗したのは判断ではなく、判断を実行に移す語彙（action space）。**

1. `set`（値を入れる）は `<select>` 前提。kintone の新UIはボタン型の独自メニューなので
   set はクリックにフォールバックし、**メニューが開くだけで値は変わらない**
2. 「開く → 候補を探す → 候補を押す」が**1往復に1操作**しか入らない。
   3項目を設定するには最低でも6〜9往復要るのに、予算は4往復
3. 開いたメニューの候補が、エージェントに渡す**要素一覧に載っていない**
   （一覧はターン開始時のスナップショット。押した結果は次のターンまで見えない）

## 予防ルール

- **エージェントが失敗したら、まず「判断が悪かったのか、語彙が足りなかったのか」を分ける。**
  思考ログを読めば区別できる。ここを混ぜると「LLMには無理だ」と誤って結論する
- **操作の語彙は、対象UIの操作単位に合わせて設計する。** `set` / `click` の2語しか
  無いUIに、独自ドロップダウンは表現できない。`select_option(ラベル, 候補名)` のように
  「開く→探す→押す」を1操作にまとめた語彙を与える
- **往復予算は「必要な操作数 × 安全係数」で決める。** 先に必要操作数を数える
- ターンごとに渡す観測は、**直前の操作で現れた要素を含める**（スナップショットの鮮度）
