## 症状（Symptom）
記事 31 の核心の節（「GPT-6 Astra は今すぐ使えるのか」）の画面の加工が、GPT がきちんと拡大して返したのに
外周余白率 69.9% / 45.8% で毎回不採用 → 節は画像なし。検閲はそれを「実測スクショが 0 枚」と
**執筆担当に 3 ラウンド連続で差し戻した**（執筆担当は画像のパスを発行できないので直しようがない）。

## 根本原因（Root Cause）
- 余白率は「外周の均一色の帯の面積比」。対象は横長のメニュー（約 2.4:1）で、3:2 の枠に最大まで拡大しても
  上下に背景が残る → 最低でも 1 - 1.5/2.4 = 37.5%。上限 32% では**どれだけ上手に切り出しても通らない**
- 検閲は画像の欠落を「どの担当が直せるか」を見ずに執筆担当へ返していた（宛先の違う指摘）

## 修正（Fix）
- 画面の加工だけ「横か縦のどちらかを 75% 以上埋めているか」で判定（`imgproc.check`・05 と 06b が共用）。
  最初 85% にしたが、本番の作り直し（横 81%・縦 66%・正しい出力）が落ちたため 75% に。縮めて真ん中に置いた
  失敗は両方向とも 55% 前後で落ちる
- 本文に書かれたラボの生パス `![…](shots/…)` は 05 が外す（画像のパスは機械が発行する）
- 本番で記事 31 を再実行 → sec-4 を採用・原稿に挿入（目視で確認）

## 予防ルール（Prevention）
1. 品質の閾値を足したら、**正しい出力が通るかを形の極端な例（横長・縦長）で確かめる**。
   合格側の実データだけで閾値を決めない（合格した画像は旧基準を通ったものだけ＝生存者の偏り）
2. 「不能条件を課すと、捏造か永久ブロックになる」（2026-09-04 の教訓）の画像版
3. 差し戻しは「その欠陥を直せる担当」に宛てる
