# `\{.*\}` によるJSON抽出は最上位が配列の出力で必ず壊れる

## 症状
LLMに `[{"text": "…"}, …]` 形式（最上位が配列）を要求したワーカーで、
抽出regex `\{.*\}` が「最初の`{`〜最後の`}`」（=配列の外括弧を除いた中身）をマッチし、
`json.loads` が2要素目以降を「Extra data」で拒否。

## 根本原因
オブジェクト用の抽出regexをコピペで流用。最上位がオブジェクトの間は偶然動く
（貪欲マッチが全体を掴む）ため、配列出力の契約を持つワーカーに混入して初めて発火した。

## 修正
`[\[{].*[\]}]`（配列/オブジェクト両対応・貪欲）に3ワーカー統一。

## 予防ルール
**LLM出力のJSON抽出ヘルパーは書き捨てで増やさず、配列/オブジェクト両対応の共通実装
（`[\[{].*[\]}]` + コードフェンス除去）を1つ使い回す。**
新ワーカーで出力契約（最上位の型）を変えたら、抽出側が対応しているかをセットで確認する。
