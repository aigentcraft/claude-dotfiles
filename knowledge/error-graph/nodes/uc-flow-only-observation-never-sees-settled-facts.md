## 症状
人間が Qiita の記事 URL を投げて「これ、導入して記事にしないと」と言った。
題材は **Claude Computer Use**（2026-03-23 発表 / 2026-04-09 に Cowork が Windows でも GA）。

weevee のジャンルは「AI ツール/SaaS 実測レビュー」そのものなのに、**発表から半年たった 2026-09-11 時点で**:

- `topics` に該当 **0 件**
- `articles` に該当 **0 件**
- `market_signals` に該当 **0 件**（Anthropic 関連は入っている — Build Days、脅威報告書）
- `keywords` に Cowork / Computer Use / Dispatch が **0 語**（Claude Code 関連は 5 語ある）

つまり企画の入り口にすら存在しなかった。人間が外から投げるまで誰も気づかなかった。

## 根本原因
release の検知が **x-listener の観測（X のタイムライン＋公式アカウントの固定枠）だけ**に乗っている。
X は流れで、話題は数日で流れ去る。だから

> **観測が「今流れているもの」しか見ていないと、流れ終わった事実は二度と観測に乗らない。**

発表当日に拾えなければ、その機能は永久に存在しないことになる。しかも読者にとっては
「半年前に出て今も使える機能」のほうが検索需要が大きい（速報より寿命が長い）。

同じ形の二次被害もある: 日本語の解説記事は発表直後に集中するので、**古い記述のまま残る**
（今回なら「macOS のみ」。実際は 4 月から Windows でも使える）。
流れを追うメディアは全部それを書いて、誰も直さない。**棚卸しをする者だけが訂正できる。**

## 予防ルール
1. **観測を 2 種類持つ** — 「流れ」（X のタイムライン）と「棚卸し」（ベンダーの
   リリースノート・変更履歴という**日付つきで残る一次情報**）。後者は取りこぼしても後から拾えるのが利点で、
   流れの観測とは目的が違う。片方だけでは企画の入り口が埋まらない
2. **キーワードに無い語は企画に上がらない** — 棚卸しで見つけた製品・機能名は、その場で
   `keywords` に足す（taxonomy の domain に紐づける）。見つけたことと企画に載ることは別の作業
3. **「古い記述が残っている」を積極的に企画の種にする** — 一次情報と出回っている二次情報の
   食い違いは、実測メディアが最も価値を出せる箇所。一次情報を読んだら
   **二次情報との差分を必ず確認する**（今回はこれが記事の切り口そのものになった）

## 状態
**未実装**。棚卸しレーン（ベンダーのリリースノートを定期に読んで `market_signals` と `keywords` に
落とす経路）はまだ無い。今回は人間が外から投げたことで 1 件だけ拾えた。
この穴が開いたままだと、次の見落としも人間が気づくまで出てこない。
