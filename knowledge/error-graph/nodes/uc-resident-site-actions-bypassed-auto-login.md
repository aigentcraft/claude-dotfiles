## ユーザーの指摘（原文）

「あと、各サイトへのログインを自動でしてくれないようになっていて、不具合が起きている。」

## 1. Plan / Context

fukugyo-hootl の巡回（Playwright の専用プロファイル）は、セッションが切れていれば資格情報で自動ログインし直す
（`withAuthenticatedPage`）。ママワークスは夜の間に毎日切れ、毎朝 7 時の巡回が再ログインしている（記録上 17 回、全部成功）。
一方、Discord で本人と会話する常駐の Claude Code は、サイトを**本人の普段の Chrome**（Claude in Chrome）で開いて読み・送る作りで、
指示文には「本人がいつも使っている Chrome（各サイトにログイン済み）」と書かれていた。

## 2. Do / The Error（2026-10-04 21:14）

- 「選考状況や企業からの連絡どうなってる？」に、常駐が「ママワークスのメッセージ画面も見に行ったが、Chrome がログアウトしていて開けなかった」
- 別のスレッドでは、企業への辞退の連絡を「OK なら Chrome から送ります」と提案していた（送れば同じところで止まる）
- 返信案を巡回側の経路で送る道具（`redraft_reply`）は「承認待ちの返信案があるスレッド」でしか使えず、常駐が自分で書いた文面には使えなかった

## 3. Check / Root Cause

- **自動ログインは巡回側にしか配線されていなかった。** 常駐の会話は「Chrome はログイン済み」という前提で、
  切れた時に戻す経路も、Chrome を使わずに済ませる道具も持っていなかった（`recovery-implemented-but-not-wired` の再発型）
- 普段の Chrome のセッションは、本人が使わない間に切れる。巡回のように毎時触っていないので、切れたまま残る
- エージェントは決まりとしてパスワードを扱わない（扱わせるべきでもない）ので、自分でログインし直せない

## 4. Act / Prevention Strategy (Fix)

- 予約 `propose_reply`: 常駐が書いた文面のまま、ふつうの返信案と同じ承認カードを出す。本人が押すと `onApprove` が各サイトの経路で送る
  （ママワークス・求人ボックスは自動で再ログインするブラウザ。前置きと相手の新着の確認も通る）
- カードを出す時に会話を取り直して指紋をそろえる（こちらが最後に送った会話で、送る直前の確認が「新着あり」と誤って止めないため）。
  取り直した会話の最後が相手の未処理の発言なら出さない（読まずに送るカードにしない）
- 常駐の指示文: Chrome のログインは切れていることがある・自分でログインしない・ママワークスと求人ボックスは記録（get_conversation）と
  承認カードで扱う・Chrome でしか見られないもの（インディード）だけ本人に 1 行でログインを頼む。「送って」と頼まれてもまずカード
- 独立レビュー（code-reviewer・HIGH 1）で直したこと: **送り先を推測しない**（同じスレッドに同じ企業のやり取りが複数ありうる。「最後に更新された記録」は
  「最後に連絡があった会話」ではない）。複数なら鍵の指定が要り、カードの前に送り先を出す。**古いカードのボタンでは送らない**
  （押されたカードが記録に引けず、記録が別のカードを指していれば中止。巡回由来の既存の穴も塞がった）。書く前に記録を引き直し、案件の順番待ちの中で書く
- selftest 567 件。故障注入 2 種（送り先の推測・古いカードの判定を外す）で FAIL を確認。22:05 に常駐を再起動して反映

## 予防ルール

- **自動回復（再ログイン・再接続）を作ったら、その資源を触る経路を全部数える。** 1 つでも外を通る経路があれば、そこで同じ失効が起きる
- エージェントに渡す「前提」（ログイン済み・起動済み）は、時間で崩れるものなら書かない。崩れた時の扱いを書く
- 認証が要る操作は、資格情報を持つ側（コード）の経路に寄せる。LLM にログインさせる道は作らない
