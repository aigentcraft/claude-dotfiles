## 1. Plan / Context
hero は「ブランドの雰囲気を出す抽象図」と定義し、文字を入れない方針だった（BRAND_STYLE: Text: none）。

## 2. Do / The Error（ユーザー指摘 2026-08-28）
- 「ヒーロー画像が何を表そうとしているのか、タイトルや記事の内容との関係がわからない」
- 実物: ティールの角丸とミントの弧、紙色の余白 — 記事（Ollama の VPS メモリ実測 等）との対応が読者に伝わらない

## 3. Check / Root Cause
1. **hero の役割を「装飾」と誤定義した** — 記事冒頭の画像は OGP にも使われる「何の記事か・結論は何か」を伝える面。抽象図は役割を果たさない
2. 文字を禁止した前提（GPT Image は日本語が崩れる）が同日に崩れたのに、hero には適用し直していなかった（節画像だけ日本語化）
3. designer の hero 企画も「主題を 1 メッセージで表す抽象図」を求める指示で、タイトル/結論との対応を要求していなかった

## 4. Act / Prevention Strategy (Fix)
- hero = タイトルカード: designer が `title_ja`（28 字以内に短縮）/ `kicker_ja` / `verdict_ja`（本文の「迷ったらこれ」から転記）/ `motif_en`（右の主題図）を企画 → `infographic_prompt.hero_prompt` が日本語 1 行プロンプト化 → GPT Image → 読み戻しでタイトル必須を照合 → 不一致なら再生成 → HTML callout にフォールバック
- **予防ルール: 画像の役割（何を伝えるか）を先に定義し、「見た人が記事との関係を説明できるか」で検収する。装飾目的の画像を記事冒頭/OGP に置かない**
