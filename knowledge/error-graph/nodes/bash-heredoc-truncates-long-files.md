## 症状

Claude Code の Bash ツールで、長いファイルをヒアドキュメントで書こうとすると失敗する。

```
/usr/bin/bash: -c: line 182: unexpected EOF while looking for matching `''
```

ファイルは**1バイトも作られない**（`ls` で不在）。

## 何が起きていたか

同じセッションで:

- 22行の JSON → 成功
- 25行の Python → 成功
- **507行の JS → line 182 で EOF エラー**
- **195行の Python → line 195 で EOF エラー**

いずれも `<<'EOF'`（クォート付き＝展開なし）で、中身の引用符やバッククォートは無関係。
失敗位置がファイル内容の 180〜195 行目付近に揃うことから、
**コマンド全体が途中で切られ、ヒアドキュメントの終端が届かない**とみられる。

エラーメッセージは「クォートが閉じていない」と言うので、
中身のエスケープを疑って時間を溶かしやすい（実際に一度そうした）。

## 根本原因

Bash ツールに渡せるコマンドの長さ（または行数）に上限があり、
ヒアドキュメントはその上限を超えると**終端行ごと消える**。
「クォートの対応が取れない」は結果であって原因ではない。

## 修正・回避

- **おおよそ150行を超えるファイルは Write ツールで書く**。
  ヒアドキュメントは短い設定ファイル・小さなスクリプト向け
- 既存ファイルへの部分変更は `python - <<'EOF'` で
  「読む→置換→書く」（置換対象の存在を `assert` で確かめる）。これは短く収まる
