## 症状（Symptom）
人間指摘「#35以降の記事が画像が変」。記事 35 の節 4〜7、記事 38・39・40 の全部の図と冒頭画像が、
大きな余白に文字が少しだけの「HTML の簡易版」の図で公開されていた（本番で確認）。

## 根本原因（Root Cause）
1. **直接の原因**: 9/23 22:39 に ChatGPT（Plus）の画像生成（Codex）が**週の**利用上限に達した
   （`resets_in_seconds` 145,836 = 約 40 時間・解除 9/25 15:09）。その間に速報レーンが 4 本を自動公開し、
   図は全部 HTML の代用描画に落ちた。消費の内訳: 9/18〜23 の週で約 260 回、そのうち読み戻し（文字照合）が
   約 4 割、公開されなかった記事（31・34・28）の画像が約 4 割
2. **本当の欠陥**: 解除後に描き直す定時の作り直しキュー（`tools/regen_images_queue.py`）はあったが、
   05（画像担当）が書き換えるのは**下書き**（`output/drafts`）と画像フォルダだけで、公開中の本文
   （`site/src/content/blog`）は変えず、**commit も push もしない**。→ 公開中の記事は、作り直しても
   本番には一度も出ない。実例: 9/21〜22 に「端で切れた図」を直した記事 5・8・13 は、直した画像が
   手元に残ったまま 2 日以上本番に出ていなかった（本番は切れたまま）
3. 作り直しの順番が「承認待ち（review）が先・公開中が後」で、読者が見ている 4 本より承認待ち 1 本が先だった
4. 未 commit の 9/23 の修正（`--redo-fallbacks`）は、端末画面（terminal・HTML で描くのが正しい設計）まで
   「簡易版」として描き直し対象に含めていた

## 修正（Fix）
- `tools/sync_live_images.py`（新設・LLM 不使用）: 画像が変わった節だけ、公開中の本文の画像ブロックを
  下書きのものに差し替え、公開中の本文 1 本と画像フォルダだけを commit・push（07 の `commit_and_push` を再利用）
  - 画像が同じ節は公開中の文言を 1 文字も変えない（公開後に直したキャプションを戻さない）
  - **書き直し中の下書き**（見出しが違う / 画像が変わった節の本文の一致率 < 0.85）は出さない。
    一致率は公開中 24 記事の全節で実測（公開時の内部リンク挿入だけ 0.87〜1.00・書き直し中 0.11〜0.82）
  - 作り直しで新しく増えた C 系の不合格だけで止める（元からの不合格で画像の差し替えまで止めない）・push 前にビルド
- `regen_images_queue`: 公開中の記事を作り直したら直後に本番へ出す / 毎回の実行の最初に「直したのに本番に
  出ていない公開記事」を出し直す（失敗の再試行・上限中でも動く）/ 並び順を published → approved → review に
- 05 `fallback_targets`: 描き直しは情報図（FALLBACK_KINDS）だけ。terminal は対象外
- 毎朝の成果チェック `live_images_drawn`: **HEAD の manifest**（= 本番）で簡易版の図を数える。
  手元の manifest を見ると「直した」記録と本番の食い違いを見落とす。上限中・解除後 24 時間は owner=auto
- テスト 18 件（本物の git + bare origin で push された中身を数える）。並び順・作り直し直後の反映・
  terminal の除外の 3 件は旧コードで赤を確認

## 予防ルール（Prevention）
1. **修理の経路は、公開の経路まで通して完了とする。** 生成物を作り直す道具を書いたら、「読者が見る場所が
   変わったか」を本番（HEAD / 配信 URL）で数える。手元のファイル・下書き・記録（manifest）は「直した」の証拠にならない
2. 下書きと公開物が同じフォルダを共有しているなら、**書き直し中の下書きの成果物を公開物に混ぜない判定**
   （見出し・本文の一致）を反映の段に持たせる
3. 作り直しの順番は「いま読者に見えているもの」を先にする
4. 外部の週上限は「待てば戻る」だが、戻るまでに公開されたものは自動では直らない。**上限の間に公開した物の
   後始末（描き直し → 本番反映）までを 1 つの経路**として作り、成果チェックで本番を数える
