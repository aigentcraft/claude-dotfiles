## ユーザーの指摘（原文）

「#71 8-3 【フルリモート】事務オペレーションスタッフ｜株式会社Leaner Technologiesにメッセージがきていて返信したが、指定の書式じゃないから受け取れないと来ていた。指定が面倒なので、LLMに判断させたいのと、機械的なボットみたいになっていないか気になる。」

（利用者は企業からの連絡だと思っていたが、実際は**こちらの Bot** の返事だった）

## 1. Plan / Context

インディードの［応募内容を作る］で承認ボタンを出せない時、人物像に無い情報が理由なら
スレッドで本人に聞き（settings の `persona.request.<スレッドID>` に質問中と記録）、
返信を `extractFacts`（「項目: 値」の正規表現 → Haiku）で読んで persona.md に登録する。
スレッドへの自由な書き込みは、別に案件担当エージェント（LLM）が受ける。

## 2. Do / The Error

#71 の応募フォーム（HERP）は履歴書・職務経歴書の**添付が必須**で、エージェントは正しく手前で止まった。
ところが続く案内は「人物像に無い情報があるため… `項目: 値` の形で返信してください」。
本人が「私の方で操作して応募しました。」と書くと、Bot は
「⚠️ 返信から登録する内容を読み取れませんでした。`項目: 値` の形で、1 行に 1 項目ずつ返信してください」と返した。
しかも質問中の記録は消えないので、**以後そのスレッドへの書き込みは全部この定型文で突き返される**状態だった
（案件担当エージェントに一度も届かない）。

## 3. Check / Root Cause

- **質問への返信の口が、案件担当エージェントより前で書き込みを握りつぶしていた。**
  情報待ちの口（`handleInfoReply`）は「読めなければ案件担当に回す」になっていたのに、人物像の口だけ
  「読めなければ書式を指定して突き返す」のままだった（同じ形の経路を洗っていなかった。3 日前の予防ルール 2 の不履行）
- 質問中の記録を消すのが「全部答えそろった時」だけで、自分で応募した・見送った後も残り続けた
- 止まった理由の言い分け（`notReadyNotice`）が**正規表現**で、任意の電話番号欄の「人物像に未記入」に反応した。
  添付（答えても進まない理由）より人物像を先に見ていた
- 書式の指定は、返信を読むのが LLM になった後も「コードで読めるように」残っていた

## 4. Act / Prevention Strategy (Fix)

- `handlePersonaReply` は読めなければ `false` を返し、`onThreadMessage` が案件担当エージェントへ回す（定型文を廃止）
- `activePersonaRequest`: 案件が応募済み・見送り・受託中・募集停止なら質問を取り下げる。案件担当が状態を変えた時も消す。
  応募内容を作り直した時（エージェント版・フォーム版）は前回の質問を消してから聞く
- `notReadyNotice`: 任意の欄を理由に数えない。**添付 → 人物像**の順に見て、添付なら
  「ご自身で応募してください。応募したらひとこと書いてもらえれば応募中にします」（`manual`・人物像は聞かない）
- 質問の文面から書式の例（`項目: ○○`）を外し「書き方は自由」に。情報待ちの質問も同じ
- 案件担当の文脈に「こちらから質問中」を渡し、指示に「書き方を指定し直さない・意図をくむ」「報告書にせず話し言葉で」を追加
- selftest 10 件（#71 の実物の理由 3 行を含む）。故障注入（添付の判定・案件担当への受け渡しを外す）で 2 件 FAIL を確認

### 予防ルール

1. **人の自由な書き込みを、書式違いで突き返さない。** 読めなければ、文脈を持つ LLM に回して意図をくませる
2. **「質問中」の状態には消える条件を必ず持たせる。** 答えがそろった時だけでなく、前提（案件の状態）が変わった時も
3. 返信の口を 1 つ直したら、同じ形の口を全部洗う（人物像・情報待ち・フォームの★要確認）。**前回のルールを書いただけで終わらせない**
4. 止まった理由を正規表現で分けるなら、**本人が次にできることの順**（関門 → 添付 → 人物像）で見て、任意の欄は外す
