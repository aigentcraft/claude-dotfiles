## ユーザーの指摘（原文）

「**毎回この再ログインが発生して、そのたびに高頻度の更新を指摘しているんだけど、
学習せず同じことを繰り返すのはなんで？**」

「毎回」＝**一度ではない。** 記録に残っているのは 2026-09-17 の 1 件だが、利用者から見れば繰り返し。

## 何が起きていたか

| 日付 | 何をしたか | 利用者に見えたこと |
|---|---|---|
| 2026-09-17 | 有人ログインの待ちで、利用者が操作中の画面を判定のために遷移させた | 1.5 秒ごとに画面が飛んで操作できない |
| 〃 修正 | 判定を**別タブ**に移した（利用者の画面は読むだけに） | — |
| 2026-09-23 | Cloudflare に 403 で止められている状態で、同じ `login --manual` を起動した | **ブラウザが 2 つ出て、片方が更新を繰り返して進まない** |

2 回目の実態: 別タブが `jp.indeed.com` を **10 秒ごとに再読込**し、毎回 403 を踏んでいた
（約 2 分で 12 回）。ブロックを解きたい場面で、ブロックを延ばす方向の要求を自動で出していた。

## なぜ繰り返したか（根因）

**① 09-17 の修正は「見えた症状」を直し、「振る舞い」を直していなかった。**
直したのは「利用者の画面を奪う」こと。「人を待つ間、自動で要求を繰り返す」こと自体は
別タブへ**移っただけ**で残った。タブが見える以上、利用者から見れば同じ「勝手に更新される」だった。

**② 予防ルールが文章にしか無かった。**
09-17 のノードに予防ルール 3 として書いてあった:
> 「判定できない」が続く経路は、無限に同じ処理を繰り返す。
> `unknown` が固定される可能性を前提に、回数や間隔の上限を置く。

**コードには上限が入っていなかった**（`PROBE_INTERVAL_MS = 10_000` で、10 分間無制限に再読込）。
文章のルールは、読まれなければ効かない。

**③ 実行前にその文章を読まなかった。**
同じサイト・同じコマンド・4 日前の記録。セッション開始時に error-graph を読む規約があるのに、
道具を選ぶ時に引かなかった。

**④ 名前で道具を選んだ。**
問題は「ログイン」ではなく「ブロック」だったのに、`login` という名前で選んだ。
その道具が**待つ間に何をするか**（再読込を繰り返す）を確かめずに使った。

## 予防ルール

- **予防ルールは文章で終わらせず、コードに落とす。** 「上限を置く」と書いたなら、
  その場で上限の定数とテストを書く。文章だけのルールは、人も AI も忘れる
- **修正の単位は「振る舞い」。** 症状を別の場所へ移しただけの修正は修正ではない。
  「利用者の画面を触らない」ではなく「人を待つ間は要求を出さない（出すなら上限つき）」
- **相手がブロックしているなら、こちらからの要求を止める。** 403 / 429 / Security Check を
  検知したら、以後は画面を読むだけにする。待機ループの中に自動で止まる仕組みを置く
- **道具は名前でなく振る舞いで選ぶ。** 使う前に「待っている間に何を送るか」を確かめる

## 結果（この指摘で何を変えたか）

`core/auth.ts` の `waitForManualLogin` に、ブロック検知と回数の上限を**コードとして**入れた。
selftest で故障注入まで確かめ、「文章を読まなくても道具が勝手に止まる」状態にした。
