## 指摘（原文）
> 回帰取得したサジェストのそれぞれすべての検索ボリュームとって同じ検索意図のクラスタ作成と、
> それぞれの競合記事の取得をしたうえで企画ができているのか？

## 答え: できていなかった
2026-09-18 に需要語 7 つ（NotebookLM 使い方 27,100 / Claude Code 料金 27,100 / Claude Code 使い方 18,100 …）を
企画したが、設計（docs/07 §6.2「サジェスト回帰 → 企画」）の 4 段階のうち、実際に踏んだのは 1 段階目の
「種の語のボリューム」だけだった。

| 設計の段階 | 実際 |
|---|---|
| サジェストを回帰取得 | **0 件**。道具（`suggest_matrix.py` / `kwcli seed-suggests`）はあるが、企画補充（02a）は呼ばない。定時にも無い |
| 全語のボリューム | 種の語 103 語のみ。サジェストが無いので派生語のボリュームも無い |
| SERP 指紋で意図クラスタ | 7 語すべて **指紋 0 件**。02a は**キャッシュを読むだけで取得しない**（`serp.load_cached`）。全 DB で 30 行 = 9/06 のさくら実験分 |
| 競合記事の取得 | 企画時点で **7 企画中 6 企画が 0 件**。競合は企画の**後**、記事に着手した時に 02c が取る。企画の構成案は競合を見ずに書かれた |

つまり seo-strategist は「語 + 月間検索数 + 自分の知識」だけで構成案を書いた。docs/07 §6.3 が要求する
「outline に競合ブロック（gap_plan）が入っていること」も満たしていない。

## なぜ起きたか
- docs/07 §6.2 は**人が道具を順に叩く手順書**として書かれ、企画補充のコードには配線されなかった
  （9/06 の実走は手作業で 1 回やっただけ）
- 02a は「SERP 指紋があれば使う」設計で、**無ければ取りに行かない**。新しい語は永久に指紋が無い
- 競合の取得は 02c（記事着手時）に置かれ、企画段階には無い。「企画に競合ブロックを必ず含める」という
  設計の要求は、02a の機械検証にも入っていなかった
- 私は 9/18 に「企画した」と報告した。**企画が設計どおりの材料で作られたかを確かめずに**、
  企画が登録されたことをもって完了とした（「作った」と「設計どおりに作った」を分けていない）

## 修正の方針
企画補充の**前段**に、材料を機械で揃える工程を配線する（LLM 不要・道具の順次実行）:
種の語 → サジェスト回帰 → 全語のボリューム → SERP 指紋で意図クラスタ → クラスタごとに競合の上位を取得・分類・gap_plan
→ その材料（クラスタ表 + 競合 gap_plan）を seo-strategist に渡して企画させる。
登録前の機械検証に「競合ブロックが outline にある」を足す。既に作った 7 企画は材料を揃えて**企画し直す**。

## 予防ルール
- **手順書は配線されるまで手順書でしかない。** 設計書に手順を書いたら、それを呼ぶコードと「踏んだか」の検証を同時に置く
- 「企画した」を報告する前に、**企画が何を材料に作られたか**を数える（サジェスト N 件・指紋 N 件・競合 N 件）
- 材料が「あれば使う」設計は、新しい対象に対して永久に材料が無い。**無ければ取りに行く**を既定にする
