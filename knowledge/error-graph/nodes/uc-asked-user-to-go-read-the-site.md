## ユーザーの指摘（原文）

「やることの通知で、WEBサイトを見て詳細を確認する、みたいなのが出てるけど、そんなの俺にやらせないでよ。」

## 1. Plan / Context

企業の連絡（サイトのメッセージ・メール）を Haiku が「やること」に分解し、本人のカードとして出す。
分解の指示には「確認する・読むだけのことはタスクにしない」と書いてあった（2026-10-03 夕方に追加）。

## 2. Do / The Error

開いているやることのうち 21 件が「求人詳細ページを確認」「スカウト詳細をマイページで確認」「企業からのメッセージを確認」型。
多くはメールの通知（スカウト・オファー・メッセージ到着）から作られていた。読むだけの作業を本人に回していた。

## 3. Check / Root Cause

- **LLM への指示（プロンプト）だけで禁止していた。** 出力を確かめる段が無く、指示を無視した出力がそのままカードになった
- 指示を足す前に作られた分も、片付ける規則が無かった
- 「読む」を引き取る担当（常駐の Claude Code は Chrome でサイトを開ける）につないでいなかった

## 4. Act / Prevention Strategy (Fix)

- 分解の結果を純関数で見分ける（サイト・ページ・詳細・メッセージなどを「確認する・見る」だけのもの。本人確認・署名・入力・返信は除く）
- 見分けたものは本人のやることにせず、秘書（常駐の Claude Code）に「代わりに開いて読み、要点と本人の判断が要る点だけを書く」よう渡す
- 既存の同じ型のやることは、片付けで取り下げる

### 予防ルール

1. **LLM に「〜はしない」と頼んだら、出力をコードでも確かめる。** 指示だけの禁止は破られる
2. **本人に回す前に「秘書にできないか」を問う。** 読む・調べる・転記するは秘書の仕事。本人に残すのは判断・本人しか知らない情報・本人の操作が必須のものだけ
