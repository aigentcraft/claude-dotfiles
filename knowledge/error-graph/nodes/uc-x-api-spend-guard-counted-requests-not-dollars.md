## ユーザーの指摘（原文）

「XのAPIの消費が激しい。ブラウザ操作で代替できるものは変えたい。」

## 1. Plan / Context

weevee の X課は 2026-09-02 から X API（Pay-Per-Use）で投稿・観測・交流を自走。人間決定⑪で
「$5 チャージ・残高 $1 未満で自動チャージ・**月次消費 $25 の機械ガード**」を決め、設計書の見積は月 ≈ $16。
引用と自発リプだけは 2026-02 の API 規制（403）でブラウザ経路にしていた。設計書には
「全ブラウザ経路なら $0 だが凍結リスクが送信系に集中するため非推奨」と書かれていた。

## 2. Do / The Error（2026-10-03 の実測 — 開発者コンソールの使用状況を閲覧）

- 30 日の実費 **$33.13**（見積 $16 の 2 倍・上限 $25 超え）。直近 2 週の水準は月 ≈ $48
- 内訳: **URL 付き投稿 79 件 × $0.20 ≈ $15.8（48%）** / 投稿の読み取り 2,390 件 × $0.005 ≈ $12.0（36%）/
  ユーザーの読み取り 207 件 ≈ $2.1 / いいね・フォロー 100 件 ≈ $1.5
- 「月 $25 の機械ガード」は**コード上どこにも金額では存在しなかった**。あったのは `X_WRITES_PER_MONTH=150`（書き込みの**回数**）だけで、
  URL 付き投稿（$0.20）と通常投稿（$0.015）を同じ 1 回に数えていた。読み取りには月の上限が無い（1 回・1 日の上限だけ）
- 記事の告知が 1 日 4〜6 本に増えた時点で、回数の上限の内側のまま金額だけが膨らんだ
- 観測は 1 日 4 回 × 約 55 件の読み取り。そのうちかなりの部分（自投稿・トレンド）は、ログイン済みの画面を開けば無料で同じ値が取れた
  （画面の応答には API の public_metrics に無い他人の投稿の表示回数まで入っている）

## 3. Check / Root Cause

- **上限を、払う単位（金額）ではなく数えやすい単位（回数）で実装した。** 単価が 13 倍違う操作を同じ 1 として数えたので、
  構成比が変わった瞬間に上限が意味を失った
- **人間が決めた数字（$25）を、実装の段で別の量（150 回）に読み替えた。** 読み替えた事実がどこにも書かれておらず、
  「機械ガードは維持」という記述だけが残った
- **見積を実費と突き合わせる仕組みが無かった。** 開発者コンソールの使用状況は 1 か月誰も見ていない。課金の自動チャージが
  「止まらない」ことを保証する一方、「増えた」ことを誰にも知らせなかった
- 「全ブラウザ経路は非推奨」の判断を、単価表（URL 付き $0.20）を見直さずに 1 か月据え置いた

## 4. Act / Prevention Strategy (Fix)

2026-10-03 実装（weevee・docs/09 §18・人間決定⑯）:
- DM 以外のすべて（観測・フォロワー同期・相手リサーチ・メンション・投稿・いいね・フォロー）を画面経由に。
  読みは画面が受け取る GraphQL 応答を v2 と同じ形に直し、xmcp と同じ `call_tool` の口で渡す（既存コードは切り替え口 1 か所だけ変更）
- レーンごとに `X_BROWSER_<LANE>=0` で API に戻せる。ログイン切れでは API に**黙って戻さない**（課金が音もなく戻るため・ops に 1 日 1 回）
- 画面自動操作の危険（凍結）への安全弁: X の「自動化の疑い」（code 226）で送信を 24 時間停止 / 連続送信の間 / 入るたびの本人確認 / 本文の読み戻し照合
- 本物の画面で読み取り全経路を確認（API 呼び出しゼロ）。送信は押す直前まで確認し、最初の実送信は定時処理で起きる

**未着手**: 金額で数える上限（API に戻したレーンと DM の分）。

### 予防ルール

1. **費用の上限は、払う単位で数える。** 単価の違う操作が混ざるなら、単価の区分ごとに数えて金額に直してから上限と比べる。
   回数で代用するなら、その読み替えを決定の隣に書き、構成比が変わったら見直す日を決める
2. **人が決めた数字を実装で別の量に読み替えない。** 読み替えるなら人に確認する
3. **従量課金を使う仕組みには、請求元の使用状況（ダッシュボード）と見積を突き合わせる検査を置く。** 自動チャージは「止まらない」仕組みであって「増えたら知らせる」仕組みではない
4. **同じ情報・同じ操作が無料の経路（ログイン済みの画面）で取れるなら、課金経路を使う理由を書けるか確かめる。** 書けないなら無料経路を既定にし、課金経路を切り替えで残す
