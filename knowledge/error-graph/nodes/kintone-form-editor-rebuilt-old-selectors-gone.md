## 症状（未修正・現状把握のみ）

フォーム設定画面のスクショ（フィールド設定パネル）が撮れない。

```
ShotUnavailable: field_settings: FIELD の候補セレクタが1つも存在しない
  ['.fm-control-single_line_text-field-gaia',
   '[class*="fm-control-"][class*="-field-gaia"]', ...]
```

**過去に撮影が成功していたアプリでも 0 件**だったので、こちらの変更や待ち時間の問題ではない。

## 何が起きていたか

kintone がフォーム編集画面を作り直している。旧 UI の
`fm-control-*-field-gaia` 系クラスは**1つも残っていない**。
実測した新しいクラス（CSSモジュールのハッシュ付き）:

| 役割 | 新クラス（前方一致で使う） | 個数（8項目・2見出しのアプリ） |
|---|---|---|
| 行 | `_appForm-row_…` | 5 |
| 行＋見出しを含む枠 | `_appForm-field-container_…` | 10 |
| **1項目ごとの枠** | `_fieldPresenterContainer_…` | **8（＝項目数と一致）** |
| 項目ラベル | `_appForm-fieldLabel_…` | 8 |
| 歯車（設定） | `_appForm-field-menu-icon_…` | 10 |

ハッシュ接尾辞（`_1w1xp_1` 等）は kintone のデプロイで変わるため、
**完全一致で書いてはいけない**。`[class*="appForm-..."]` の前方一致で持つこと。

## まだ分かっていないこと（2026-09-14 追加調査でも未解決）

歯車は**その項目の右上角**に出る（隣の項目の左端と数pxで重なるため、縦位置だけで
選ぶと隣の歯車を掴む）。ホバーで歯車を出し、Playwright の要素クリックで押すと
**クリック自体は成立する**（インターセプトなし・アイコンが活性表示に変わる）。
それでも**設定パネルは開かない**。試した操作はすべて空振り:

| 試した操作 | 結果 |
|---|---|
| 項目をダブルクリック | 開かず |
| ホバー→行の歯車を座標クリック | 要素が「選択」されるだけ |
| 項目をクリックして選択→右上の歯車 | 開かず |
| 要素クリック（Playwright の actionability 経由） | クリック成立・パネルは開かず |
| 出現要素の差分（dialog/modal/panel 系） | **新規0件** |

つまり「歯車＝設定パネルを開くボタン」という前提自体が誤っている可能性がある。
次にやるなら**人が1回操作するところを記録する**のが早い（推測での総当たりは高くつく）。

## なぜ今まで気づかなかったか

**手前の故障がこの故障を隠していた。** デモアプリの構築が
`未知の型` と `CB_VA01` で落ちていたため、撮影処理にそもそも到達していなかった
（[[writer-vocabulary-crashes-demo-app-build.md]]）。構築を直した瞬間に表に出た。

「Q05/Q09 が慢性的に落ちる」の原因を撮影カタログの作り込み不足だと診断していたが、
**少なくとも一部は外部UIの変更**だった。

## 2026-09-18 追加調査 — 押すべきボタンは特定できたが、それでも開かない

### 分かったこと（確定）
- 歯車の実体は `div` ではなく、その中の **`<button>`**。React の `onClick` を持つのはこれだけ
  （`elementsFromPoint` + `__reactProps$` で実測）。DOM の入れ子:
  `div[class*=appForm-hover-menu-icon] > div.sc-…__container > BUTTON > span > svg`
- ボタンは**選択／ホバー中の項目の枠の内側・右上**に出る
- **1項目の枠の中にボタンは2つある**。左は**幅のリサイザー**
  （押すと `Draggable item 品番_resizer was dropped.` が出る）、右が歯車。
  座標や「枠の右上に最も近い」で選ぶと**隣の項目のリサイザーを掴む**

### 効かなかった操作（すべて実測・DOM要素数も本文も1文字も変化なし）
| 試行 | 結果 |
|---|---|
| 座標クリック / Playwright の要素クリック | 変化なし |
| JS から `button.click()` | 変化なし |
| フォーカス + Enter（`onKeyDown` 経路） | 変化なし |
| 項目のクリック / ダブルクリック | 変化なし |
| ヘッドレスではなく**画面ありのChromium**＋段階的なマウス移動 | 変化なし |
| 幅1920で全面撮影（右に見切れた設定欄を疑う） | そんな欄は無い |
| 新規デモアプリ / 通常運用アプリ(app55) / 最古のアプリ(app1) | すべて同じ |
| console / pageerror | **エラーなし** |

### まだ潰せていない仮説
1. この歯車は**フィールド設定を開くボタンではない**（別の機能のアイコン）
2. 合成イベントでは開かない作りになっている（人の操作以外を弾く）
3. アプリが特定の編集状態のときだけ開く

**次の一手は「人が1回押して、何が出るかを見せてもらう」**。
推測の総当たりはここまでで相当なコストを使った。人の10秒で確定する。

## 予防ルール

- 外部SaaSの画面に依存する撮影は、**セレクタが全滅したことを型として検知**する
  （`ShotUnavailable` は既にある。これを「記事の失敗」ではなく
  「外部変更の疑い」として集計する経路がまだ無い）
- 故障が重なっているときは、**手前を直すと奥が出てくる**前提で計画する。
  1つ直して「解決」と報告しない
- ハッシュ付きクラス名は前方一致で持つ。完全一致は次のデプロイで壊れる
