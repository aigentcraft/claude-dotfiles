## 症状

note の承認依頼が「画像がない」で**6回続けて人間に差し戻された**（note#18〜#24、10/1〜10/11）。
#18 の理由は「画像のリミット解除されたからやって」。次の #25 も画像なしのまま承認待ち5日。
note は12日間公開ゼロ。

## 何が起きていたか

9/25 の修正（[[exception-split-into-sibling-escaped-existing-handlers]]）で、画像の利用上限に当たっても
note を落とさず「作れた画像だけで続行」し、画像なしの事実を承認依頼に1行添える形にした。
狙いは「書き上げた本文を失わない」で、それ自体は正しかった。ただ、その先の**承認依頼まで進めた**ため、
人間が受け取るのは「出せない成果物」になり、差し戻し → 即時作り直し → また画像なし、を繰り返した。
差し戻し理由は note-writer に渡るが、画像を作れないのは書き手の問題ではないので、届いても直せない。

## 修正（2026-10-16）

- 本文は検閲を通った時点で保存する（status='draft'・画像の作り方のメモも一緒に）。
  上限中は**承認依頼を出さずに待つ**
- 解除後の定時run（毎回 `01_compose --resume-images`）が、作れていない画像だけを作ってから承認依頼を出す
- 画像待ちの間は新しい note を作らない（待ちが積み上がらない）。note停止の警告には「画像待ち」と出す
- 上限以外の失敗（プロンプト起因など）で作れなかった図は、従来どおり外して依頼する
- 独立レビューの指摘で追加: 定時runだけが続きを作ると、12:13 に解けた上限で翌朝まで約17時間待つ →
  解除の瞬間に承認回収（15分毎）が1回だけ続きを作る（解除は上限1回につき1回）。続きの作成は排他ロックで同時に1つだけ、
  初回の生成中（承認回収からの作り直し）の note には手を出さない（どちらも承認依頼が2通出る経路）。
  作る画像が無い note は上限中でも待たせない

## 予防ルール

- **フォールバック（代用品で続行）は、受け取る人が受け入れる場合だけフォールバックになる。**
  承認者が毎回却下するものを出すのは、失敗を人間に回しているだけ
- **「本文を守る」と「依頼を出す」は別の判断。** 守るもの（書いた本文）を保存したら、
  依頼を出すのは成果物がそろってからにする
- **同じ理由の差し戻しが2回続いたら、その理由が直せる担当に届いているかを見る。**
  画像の上限は書き手には直せない
- 関連: weevee の [[uc-approval-requested-with-non-gpt-images]]（関門は原因ではなく結果で書く）
