## ユーザーの指摘（原文）

「**ビルドインパブリックは要らないって。** Kintone の開発とか保守の業務委託が目的なんだから、
そのために**どんな記事書かないといけないかを自立して考えて実行するllm組織**でしょ。」

「要らないって」＝**すでに言った**。3本目でようやく根因に届いた。

## 何が起きていたか

note の記事が3本続けて人間差し戻しになった。

| | 日付 | 種別 | 差し戻し理由 |
|---|---|---|---|
| note#9 | 09-03 | build_in_public | 「kintoneに関する記事じゃない」 |
| note#10 | 09-09 | build_in_public | 「kintoneのアカウントなので〜実務の話しか書かない」 |
| note#11 | 09-10 | build_in_public | 「ビルドインパブリックは要らない」 |

1本目と2本目のあと、私がやったのは:

- 書き手の契約（`agent.md`）に「**題材の範囲**」という禁止条項を足す
- 差し戻し理由の履歴を「直近1件」から「人間差し戻し最大5件」に広げる

つまり**制約（やってはいけないこと）を足した**。それでも3本目が同じ場所に戻ってきた。

理由は、私が一度も読まなかった文書にあった。レーンと目的の正本
（`skill_refs/note_strategy.md` と組織設計書 `docs/09`）にはこう書いてあった:

> noteの目的 = **①AI×自動化KWの流入面 + ②人格と証明**
> Build in Public: 「**AIエージェント組織19体が自動運営している事実そのものが唯一無二のネタ**」
> KPIは**直接CVを追わない**
> 頻度: case_story → build_in_public → field_essay の**3レーンを順に**

さらに Python 側の `KIND_CYCLE` が、その順番を機械的に強制していた。

**エージェントは逸脱していない。設計書がそう書いていて、そのとおりに書いていた。**
制約を足すのは、アクセルを踏んだままブレーキを増やす作業だった。

決定的なのは、**実測はすでにあった**こと。週次レポート（08-17 / 08-24 / 08-31）は
build_in_public の初速が case_story の 1/5 であることを測り、08-31 には
「開発過程の話が主題化しkintoneとの接続が薄れると差し戻されるリスクが見える」とまで
書いていた。**測れていたのに何も変わらなかったのは、レーンが戦略文書で固定されており、
「何を書くべきか」が誰の判断でもなかったから。**

## 根本原因

**目的を書き換えずに、制約だけを足していた。**

- 制約は「やってはいけないこと」を減らす。目的は「何をやるべきか」を決める。
  目的が古いままだと、禁止されていない範囲で**同じ方向に**戻ってくる
- 目的が文書化されていない（あるいは古い）仕事は、**代理指標に最適化される**。
  ここでは「流入とビュー」。事業目的（受注）は設計書に一度も書かれていなかった
- 「順番を機械が決める」ものは**誰の判断でもない**。ローテーションは目的から切り離されて
  いるので、目的が変わっても自動では追随しない

## 修正

- **目的を書き換えた**（人間決定）: pullieの事業目的＝kintoneの開発・保守の業務委託の受注。
  noteはその面であり、note自体の数字を伸ばすことが目的ではない。旧目的は取り消さず保存
- **build_in_public を題材から廃止**（旧定義はコメント/引用で保存）
- **「今回何を書くか」を書き手の判断に戻した**（`KIND_CYCLE` のローテーションを降格・
  `NOTE_AGENTIC_TOPIC=0` で復帰可）。材料の並び順も直した — 旧版は**第一かつ最大の材料が
  「今週の運営実データ（Build in Public用）」**で、材料が実質レーンを決めていた
- **選んだ理由を出力させる**（`why_this_topic`）。目的に効く理由が言えない題材は選ばない
- 同期: `note_strategy.md` / `agent.md` / `SKILL.md` / `note_style.md`（タグ）/ `docs/09` /
  `01_compose.py` の6箇所。**目的の変更は制約の変更より波及が広い**

## 予防ルール

- **同じ理由の差し戻しが2回続いたら、禁止条項を足す前に「その仕事の目的を定義している
  文書」を読む。** 3回目まで気づかないのは、制約側だけを見ているから
- **制約を足す前に問う: 「この振る舞いを*指示している*文書はどこか？」**
  逸脱に見えるものの多くは、どこかに書いてある指示への忠実な実行
- **エージェントに任せる仕事には、目的を明示的に書く。** 目的が無ければ代理指標
  （ビュー・件数・速度）に最適化される。それは誰も決めていない目的である
- **「順番を機械が決める」場所は、判断が消えている場所。** ローテーション・ラウンドロビン・
  交互を見つけたら、それが目的から導けるか確認する。導けないなら判断を担当者に返す
- **実測が既にある場合、なぜそれが行動に繋がっていないかを問う。**
  「測れているのに変わらない」は、たいてい判断の持ち主がいないことを意味する
