## 症状

記事45の再執筆（自己批評→改稿パス）がクラッシュし、その日の新規記事が止まった。

```
ValueError: SLUG行が見つかりません:
  I reviewed the repo (README, `docs/01-12`, `workers/`, `agents/`, `products/`,
  `site/package.json`, `scheduler/README.md`) and the existing project `CLAUDE.md`.
  That file is already extensive, but it'…
```

ライターが記事ではなく**リポジトリの調査結果**を返している。`/init` の応答そのもの。

## 何が起きていたか

- `llm_calls` の記録は **ok=1**。課金もされている（$1.63）
- ただし **num_turns=51**（正常時は1）・489秒。**タスクを受け取れず、リポジトリを51往復探索した**
- 送っていたプロンプトの実測: 土台13,720字 + 原稿6,746字 + 指示 ≒ **21,000字超**
  （土台にはファクトシートが別途入るので実際はさらに大きい）
- 既知のしきい値: **5,479字=正常 / 22,369字=未達**
  （[[prompt-never-arrived-but-the-run-looked-successful.md]] 2026-09-12 実測）

つまり **同じ故障の再発**。前回の手当ては X 課の観測本文に `MAX_TASK_CHARS=8000` を入れた
だけで、**プロンプトを組む他の場所（ライターの自己批評パス）には何も入っていなかった**。
前回は「届かない」症状が「何を進めますか？」、今回は「リポジトリを調べました」だったので
同じ故障に見えなかった。

## なぜ痛いか

1. **成功に見える**（ok=1・課金あり）ので、失敗として検知されない
2. **クラッシュが記事を止める**。自己批評は品質向上の任意パスなのに、
   そこで落ちると初稿ごと失われて `draft` に滞留する
3. 再試行しても**プロンプトの大きさは変わらない**ので同じ場所で落ちる。
   差し戻し上限まで回って破棄される

## 対策（案・未実装）

1. **落ちない**: 自己批評パスの出力が解釈できなければ**初稿を採用**して続行する。
   同ファイルには既に「改稿で規定字数を割ったら初稿を保持」という安全弁があり、その横展開
2. **検知する**: 「SLUG行が無い」かつ「往復数が異常に多い」＝プロンプト未達の型として
   `ok=False` にし、専用のエラー名で記録する（汎用クラッシュに埋もれさせない）
3. **そもそも超えない**: プロンプト長を組み立て時に測り、しきい値を超えたら
   材料をファイルに書いて**パスを渡す**（エージェントに読ませる）か、段階分割する

## 予防ルール

- **プロンプトを組み立てる場所は1箇所ではない。** 大きさの上限を入れるときは、
  `grep` で全ての組み立て箇所を洗い出して同時に入れる（列挙は閉じない）
- **同じ根本原因でも症状は毎回変わる。** 「何を進めますか？」と「リポジトリを調べました」は
  どちらも『タスクが届いていない』。症状名で既知/未知を判断しない
- **任意の品質向上パスは、失敗しても本流を殺さない形で挟む**
