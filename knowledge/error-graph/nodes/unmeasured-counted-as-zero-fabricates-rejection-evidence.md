## 症状

AI組織の学習ループが「効かなかった」という**棄却知見を捏造しうる**状態だった。

実測（2026-09-06）:
- X投稿 `status='posted'` 98本のうち **29本（quote全件）は `x_post_id` が保存されず、
  `impressions` / `likes` が永久に NULL**（投稿ワーカーが投稿IDを回収しないため、
  観測ワーカーの更新条件 `x_post_id IS NOT NULL` に一生入らない）
- 判定ゲートの入力は `SUM(COALESCE(impressions,0))` で、**NULL と 0 を同一視**
- 集計表示は quote を `平均impr=None エンゲージ率=None%` と出す

決定的だったのは、**移行計画書そのものが同じ誤りを踏んでいた**こと。
設計思想の根拠として3箇所で引かれていた

> 「91投稿中 **84件がいいね0**」は少ない試行でも言える。棄却は安く、発見は高い

を再現すると **57（実測0）+ 27（一度も計測されていないquote）= 84**。
「反応が無かった」ではなく「測っていない」が4割近く混ざっていた。

## 根本原因

**欠損（NULL）と観測値ゼロを、集計の時点で区別していない。**

危険なのは、これが「少ない試行でも棄却は言える」という**正しい設計思想と組み合わさる**とき。
未計測は集計上「n はあるのに反応ゼロ」という形になるため、
**最も強い棄却証拠の見た目**をまとう。しかもこの組織では棄却知見も
`domain_knowledge` へ昇格し、全エージェントのプロンプトに注入される。
つまり **測っていないことが「効かないという知識」に化けて組織全体へ配られる**。

上流には計測経路の欠落（投稿IDを回収しない）があるが、
**上流が壊れていても下流の集計が両者を区別していれば、汚染は止まる**。

## 修正

- 集計SQLは `SUM(値)` と **`SUM(値 IS NOT NULL)`（計測済み本数）を必ず分けて出す**
- 未計測のセルは `0` ではなく **状態として出す**（「計測済み0本 / 未計測」）。
  率は出さない（分子が1〜2件のとき率は差を「倍」に見せる）
- 判定ゲートの母数は **計測済み本数**で数える（未計測の試行は実験として成立していない）
- 集計に**窓を明記**する（同一プロンプト内に14日 / 7日 / 直近30件が同居していた）
- 計画書の該当記述を実測で訂正し、「この数値を根拠として引かないこと」を明記

実走検証: 修正後の材料で分析エージェントを走らせたところ、
quote を「エンゲージ率0%」ではなく **「未計測のため集計から除外」と明記**し、
部門平均も「quote除く」で計算した。さらに計測欠落を自分で
「要人間判断」に上げた（**汚染された材料では出てこない反応**）。

## 続報（2026-09-07）— 未計測だった型が、実は最良の型だった

翌日、上流の計測欠落そのものを回収した（送信経路には触らず、観測側で自タイムラインと
突き合わせて `x_post_id` を結線）。**29/29 が一意に一致し、未計測はゼロになった。**

回収された実測は **impressions 4,499 / likes 20** で、
**それまでDBが知っていた全体（1,709imp / 11likes）を上回った**。
1本あたり155impは他の型（約25imp）の6倍で、
**「反応ゼロ」として数えられていた型が、実際には全impressionsの72%を稼いでいた**。

この事実は本ノードの主張を最も強い形で裏づける — 未計測を0として扱っていれば、
組織は「引用は効かない」という**正反対の知識**を学び、最良の打ち手を自分で捨てていた。
手順は [[recover-ids-by-reconciling-observations-not-send-path.md]]。

## 予防ルール

- **`COALESCE(x, 0)` を集計に書く前に必ず問う: その NULL は「0だった」のか「測っていない」のか。**
  前者なら 0 で正しい。後者を 0 にした瞬間、観測していない事実が観測結果に化ける
- **「N件中M件が反応ゼロ」と書く前に、分母のうち何件が計測済みかを出す。**
  分母に未計測が混ざった比率は、事実の形をした捏造
- **欠損に解釈を添えない。** 0 に丸めるのも、`None` に「おそらく低い」と添えるのも同じ誤り。
  出してよいのは「測れた本数 / 測れなかった本数」という母集団つきの事実だけ
- **計画書・設計文書の数値も検証対象。** 前提として引用する前に自分で再現する。
  正しい設計思想が、汚染された数値を根拠に持っていることがある
- **上流の計測欠落を直せない状況でも、下流の集計で両者を分ければ汚染は止められる。**
  計測の修理を待たずに、まず「混ぜない」を入れる
