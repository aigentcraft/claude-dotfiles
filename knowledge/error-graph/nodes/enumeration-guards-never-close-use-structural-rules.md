## 症状
Bash を持つエージェント（同一ユーザー権限）から監査台帳 `logs/lab_guard.jsonl` を守るために
禁止パターンを列挙した。敵対的再検証のたびに新しい回避が見つかった:
`cd ../../..`（末尾スラッシュ無し）→ `cd ..; cd ..; cd ..`（分割）→ `A=..; $A/$A/$A`（変数）→
`$HOME` / `%USERPROFILE%` → python `os.chdir` 連打 → `Path.cwd().parents[2]` → `cd rec && cp`（サブ dir）→
`shutil.copy` / `docker cp` / `node fs` / `Out-File` / heredoc。**3 ラウンド回しても閉じなかった。**

## 根本原因
「書込み形」「パス形」を列挙する設計は、攻撃面が無限（言語×シェル×変数展開×エンコード）なのに
防御が有限。列挙を増やすほど誤拒否（正規操作の巻き添え）も増える。

## 修正
1. **構造ルールに反転**: 「`..` は 1 つでも拒否」「ホーム/環境変数のパスを使わない」「cd の先は下だけ」
   「`logs/` に触らない」「Read/Grep も同じ規則」「台帳に書けなければ実行させない」。深さや形の判定をやめ、
   0 か 1 以上か で判定する。例外は構造的なもの 1 つだけ（共有道具の固定の隣 `../_tools/`）
2. **録画後の接触検査はホワイトリスト**: 書込み形を列挙せず「録画後に rec/・shots/・同名に触る行は全部 ng、
   読み取り専用の既知コマンドだけ除く」
3. **限界を文書に書く**: 同一ユーザー権限の Bash エージェントを正規表現で完全に封じることはできない。
   機械検査は「事故と手抜きを止める物理検査」であって暗号学的保証ではない。最終の担保は reviewer の判断と人間の事後確認

## 予防ルール
1. ガードを足す前に「攻撃面は有限か」を問う。無限なら列挙せず構造で書く
2. 構造ルールは「0 か 1 以上か」で判定する（深さ・回数・形の積算は回避される）
3. 例外は構造的な理由がある 1〜2 個に限り、実走ログ（過去の正規操作）で誤拒否を数えてから入れる
4. 閉じないものは閉じないと書く。「守っている」と書いた文書が一番危ない
