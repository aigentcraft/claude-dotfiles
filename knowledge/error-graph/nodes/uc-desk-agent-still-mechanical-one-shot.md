## ユーザーの指摘（原文）

「やっぱりどうしても機械的な対応しかできていない気がする。裏にclaudecodeをクロードインクロームとコンピュータユーズなど自由に手を動かせる状態を作って常駐させてディコード上でやり取りできるようにして。」

（同じ日の朝に「機械的なボットみたいになっていないか」と指摘され、書式の指定を外す修正をした直後）

## 何が起きていたか

スレッドの書き込みに答える「案件担当エージェント」は、書き込みのたびに `claude -p` を 1 回だけ起動していた。
- **会話の記憶が無い。** 毎回 DB と直近 15 件の発言から文脈を組み立て直し、前のやり取りの理解は持ち越さない
- **手が縛られていた。** Chrome は読むだけ（クリック・入力なし）、操作は決まった 10 種類の「予約」だけ、シェルもデスクトップ操作も無い
- 常駐が先に「💭 確認しています…」と定型文を出し、答えは報告書の形になりやすい指示だった
- 人物像・情報待ちの口は、LLM より前に正規表現で読んで定型文を返していた

朝の修正は「書式を指定しない」という表面だけを直し、**LLM が決まった通路の途中に 1 回挟まるだけ**という骨組みを変えなかった。

## 根本原因

- 「LLM に判断させたい」を、「決まった経路の分岐を LLM に選ばせる」と読み替えていた。利用者が求めていたのは、
  文脈を持ち続け、自分で調べ、自分で手を動かす**担当者**だった
- 安全のために道具を削った（9/26 のレビュー: Chrome を読むだけに）ことが、利用者の目には「何もできないボット」に映っていた。
  **削った理由と引き換えに失ったものを、利用者に確かめていなかった**
- 1 件ずつ指摘された症状（書式・無反応・定型文）を個別に直し、同じ原因（一問一答の作り）に気づかなかった

## 予防ルール

1. **「機械的」と言われたら、文面ではなく骨組みを疑う。** 記憶の有無・手の自由度・定型文の割合を数える
2. 会話の担当は**続いたセッション**にする（スレッドごとに同じ Claude Code のセッションを保ち、再起動しても `--resume` で戻す）
3. 安全のために手を縛る時は、**何ができなくなるかを利用者に示して選んでもらう**。黙って縛らない
4. 同じテーマの指摘が 2 度来たら、症状の修正を止めて、作りを見直す提案をする
