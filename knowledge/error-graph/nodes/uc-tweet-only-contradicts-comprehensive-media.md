## 指摘（原文）
> AIに関する情報を網羅して構造的に整理するのが目的のこのメディアで、Xで済ませるなんてありえない

## 何が起きていたか
企画補充で、月 27,100 回検索される「NotebookLM 使い方」と 18,100 回の「Claude Code 使い方」を
**記事にせず X の単発投稿に回して** 0 本で終えた。仕組みは 2 段:
1. 企画スコア（SEO 適性 × X 適性）の verdict に `tweet-only`（SEO で勝てないが X で伸びる）があり、
   02a はそれを **topics に入れず market_signals へ回す**
2. seo-strategist のブリーフと指示書がその運用を説明しているため、**strategist 自身が route='tweet-only' を選ぶ**
   （X 適性のスコアが 0.0 でも）

さらに「同じ製品名 + 同じ動詞類」の語彙一致だけで「既存企画と同じ意図」と判定して止めるゲートが、
月 18,100 の語を需要 0 の記事（スマホで Claude Code を操作）に「吸収しろ」と言っていた。

## なぜ起きたか
- 2026-09-06 に「メディアは SEO・X は X・軸は相乗効果」の指示を実装した時、**「SEO で勝てないなら記事にしない」**
  という判断を機械に持たせた。だがこの媒体の目的は**網羅して構造化すること**であり、
  「勝てるか」は優先順位の材料であって、書くか書かないかの判断材料ではない
- 「同じ検索意図は 1 本に統合」の指示を、**語彙の一致で機械的に止める**形にした。統合するか別に立てるかは
  編集判断で、docs/14 §6 の機械ゲート 3 種（法令・不可逆・物理）に当たらない
- 同じ方針がコード（02a / 02 / planning）・ブリーフ・指示書・参照資料・設計書の **6 箇所**に書かれていた

## 修正
- `tweet-only` / `skip` による**不登録を廃止**: 企画スコアは順位づけの材料に戻す。X 適性は X 課への申し送り
- 語彙の同意図判定を「止める」から「**近い既存企画を strategist に見せて判断させる**」に
  （SERP 指紋 = Google が同じ意図と言っている物理的事実は残す）
- 止められていた 3 語（Claude Code 使い方 / Notta 料金 / Notta 使い方）を記事として企画

## 予防ルール
- **媒体の目的を、個々のゲートより上に置く。** 「網羅」が目的なら、機械が「書かない」を決めてはいけない。
  機械が決めてよいのは順番だけ
- 人間の指示を実装するとき、**「何を優先するか」なのか「何をやらないか」なのか**を区別する。
  前者を後者として実装すると、目的そのものを壊す
- 品質・編集の判断をゲートにしたくなったら docs/14 §6 の 3 種に照らす。当たらなければ「材料として見せる」形にする
