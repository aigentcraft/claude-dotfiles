## 症状
ライターが下書きの兄弟記事にリンクを張る → 自分の計器は合格 → 承認前ゲートも合格 →
**公開時に機械が黙ってアンカーを外す**。ライターには何も返らない。本文には
「こちらの記事で」の文だけが残り、リンク先が無い。

## 根本原因
同じ問い「この slug にリンクしてよいか」に、4 つの答えがあった。

| 場所 | 定義 |
|---|---|
| ライターの計器 | rejected 以外（下書きも含む） |
| 承認前ゲート | ビルド済みページに実在 **または** 承認待ちの兄弟（独自の例外） |
| 承認前ゲートの文言 | 計器と別の文（「存在しない」vs 後に揃えた「公開されていない」） |
| 公開時 | サイト上の md ファイル |

前の 3 つは通し、最後の 1 つだけが厳しく、しかも黙って直す。
「07 が公開時にテキスト化する」と**コメントで設計として書いてあった** — 黙って直すことが仕様になっていた。

## 修正
- 集合は 1 つ: **公開済みの記事だけ**（ライターに渡す一覧も元からそれだった）
- 文言は 1 つ: `internal_links.problem(href)` を計器とゲートの両方が呼ぶ
- 公開時に外したリンクは**記録に残す**（`publish.links_unlinked` イベント + 警告ログ）

## 予防ルール
- 「同じ問いに答える述語」が 2 箇所目にできた時点で単一ソースに寄せる。
  コメントに「後段が直す」と書いてある箇所は、**後段が黙って直している**印
- 機械が成果物を書き換えたら、書き換えた事実を**その成果物の作者に届く場所**に残す
- ゲートの文言はゲートが持たず、計器と同じ関数から取る（文言が別々に育つと、作者は同じ指摘だと気づけない）
