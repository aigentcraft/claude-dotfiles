## 症状

市場感知（`x/02_listen`）が3日間停止。毎runこれだけがログに出る:

```
../x_pipeline/02_listen.py 失敗 args=()
```

一方 `llm_calls` では **その呼び出しは成功（ok=1・課金あり）** と記録されていた。

## 何が起きていたか

エージェントの応答本文を読むと、こう返していた:

> 特に指示がありませんが、現在の状況を簡単に共有します。作業ツリーには未コミットの
> 変更があり…**何を進めますか？**

これは **`claude -p` にプロンプトが届かなかったときの挙動**（CLAUDE.md だけ読んで
会話調で聞き返す）。つまり課金も応答もあるのに、**こちらの依頼は1文字も渡っていなかった**。

原因は3つの重なり。

### ① stdin への書き込み失敗を握り潰していた

```python
    def _writer() -> None:
        try:
            proc.stdin.write(prompt)
            proc.stdin.close()
        except (BrokenPipeError, OSError):
            pass          # ← 未達が「無かったこと」になる
```

### ② プロンプトが大きいと届かない

同じエージェント・同じ経路で実測:

| プロンプト長 | 結果 |
|---|---|
| 5,479字 | **正常にJSONを返す** |
| 22,369字 | 「特に指示がありませんが」＝未達 |

### ③ そして自己増悪していた

- 解析に失敗 → 呼び出し側が `jsonx.extract_json(text)`（`default` 無し）で例外 → **ワーカーが落ちる**
- 落ちるので `x_observations.analyzed` が更新されない
- 未分析が積み上がる（実測 **414件**）→ プロンプトがさらに膨らむ → **次も落ちる**

止める力がどこにも無く、材料が増えるほど確実に失敗する構造だった。

## 修正

- `_writer` の例外を捨てず記録し、**stdin未達なら CLI が何を返していても `ok=False`**
  （未達を「成功した変な応答」と取り違えない）
- 呼び出し側は `default={}` で fail-soft にし、解析できなければ
  **観測を消費済みにせず次回へ回す**（分析していない材料を消さない）
- プロンプトに入れる観測本文を**件数ではなく文字数で切る**
  （1件の長さはばらつくので、件数では総量が決まらない）

## 予防ルール

- **「成功」の定義に、依頼が届いたことを含める。** 課金・応答・exit=0 は
  「こちらの依頼が渡った」ことを何ひとつ保証しない
- **`except ...: pass` を書いたら、そこが無言になる経路を一度たどる。**
  特に入力の送出・記録・後始末は、失敗しても上流が気づけない位置にある
- **外部プロセスへ渡す入力にサイズ上限を置く。** 上限は件数ではなく**バイト/文字**で切る。
  件数上限は「1件あたりが一定」という暗黙の前提があり、実データはそうならない
- **失敗すると入力が消費されない処理は、自己増悪を疑う。**
  「失敗 → 未処理が増える → 入力が重くなる → また失敗」は放っておくと必ず悪化する
