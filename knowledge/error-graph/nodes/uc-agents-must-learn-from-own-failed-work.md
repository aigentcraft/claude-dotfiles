# 「どう作ったものがダメだったのか、自分の過去の作業を見返して学習しないとダメ」

## 症状（ユーザー指摘）
検品→差し戻し→作り直しの流れは確認済みでOK。ただし各エージェントが
**自分の過去の失敗作を見返して学習する**仕組みがない、という指摘。

## 実態（指摘どおりだった）
- 差し戻しループ＝「今回の指摘を直す」仕組みであって「癖を直す」仕組みではなかった
- ダッシュボードに証拠が出ていた: 同一チェックの繰り返し不合格が Q09×8・Q03×8・Q11×7…
  ＝**同じ作り方の失敗を14日間繰り返している**
- 決定的な欠落: **失敗作そのものが消えていた**。視覚検閲不合格の画像は削除、
  再生成は上書き、差し戻しドラフトも上書き — 「どう作ったものがダメだったのか」の
  実物が残らず、原理的に見返せなかった

## 修正（既存の知見注入パイプに「自己回顧の生産側」を接続）
1. **失敗作の保存**: 05視覚検閲の不合格画像を退避（不合格理由+生成プロンプトの
   サイドカー付き・公開ディレクトリからは従来どおり除去）/ 04の差し戻し再執筆は
   前版ドラフトをhistoryへ退避
2. **knowledge-curator（L4・毎朝）に自己回顧素材を追加**: 視覚検閲failダイジェスト・
   承認前ゲート差し戻し・繰り返し不合格（2回以上）・退避済み失敗作（Readで実見）
3. **agent_scope付き教訓として昇格** → 既存のfeedback_loop注入で本人のプロンプトへ
   （注入パイプ・agent_scopeフィルタは実装済みだった — 欠けていたのは生産側だけ）
4. ✅実走: 初回キュレーションでwriterの構造的な癖6件が即日昇格
   （例:「HTMLコメント図解指示は実imgタグの代替にならない（Q09×8回）」）

## 予防ルール
1. **生成物を捨てる時は学習用の退避とセットにする**。「不良を公開に残さない」と
   「失敗から学ぶ」は両立できる（削除→退避+サイドカー）。消した失敗は学習できない
2. **同一チェックの繰り返し不合格は「学習ループ欠落」のシグナル**として扱う
   （個別の再差し戻しで消耗せず、ループ自体を疑う）
3. 学習の仕組みは「注入側があるか」だけでなく**「生産側（誰が・いつ・何から教訓を
   作るか）」まで結線されているか**を確認する。片side実装は動いていないのと同じ
4. 過去記録への訂正注記は、消費側の切り詰め（先頭N字注入）を考慮して**文頭に置く**
