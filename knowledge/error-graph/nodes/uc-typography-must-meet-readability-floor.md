## ユーザーの指摘（原文の意図）

「WEBサイトのトップページの文字、小さすぎる文字が結構ある。視認性を高めないと閲覧者が
読めなくて離反しそう。レイアウトやデザインを崩さずにポイント数を上げてほしい」（2026-08-19）

## 症状

トップページの読ませるテキストの大半が 9.5〜13px に分布していた（サービス説明13px・
About本文14px・お客様の声の補足12.5px・相場表ヘッダ11px・注記11px・フッター法務10.5px等）。
**同種の指摘は2回目**: 2026-08-09 に記事本文でも「文字が小さい」→14px から16px へ引き上げ済み
（site/src/pages/articles/[...slug].astro にコメントが残っている）。

## 根本原因

- A3デザイン案（.dc.html）の「高忠実度移植」を正としたため、デザインモックの
  ミニマル系マイクロタイポグラフィ（9.5〜13px）がそのまま本番に持ち込まれた。
  モックの見た目の緻密さと、実読者（40〜60代の現場責任者・経営層）の可読性は別物
- 最小フォントサイズの床（floor）がどの検品層にもなかった: reviewer は記事本文のみ、
  visual-inspector はスクショを**等倍以上で実見**するため「物理的な小ささ」を体感できない
- 記事本文の引き上げ（8/9）を「その箇所の修正」で終わらせ、サイト全体の
  タイポグラフィ規約に一般化しなかった（点の修正・線の学習漏れ）

## 修正（2026-08-19）

トップページ+共有ヘッダー/フッター+記事カードメタの約67箇所を、階層（大小関係）を
保ったまま一律 +1px 底上げ。9.5→10.5 / 10→11 / 10.5→11.5 / 11→12 / 11.5→12.5 /
12→13 / 12.5→13.5 / 13→14 / 14→15（主要本文）。見出し・数字等の大きい文字は不変。
1440/700/375 の3幅で横オーバーフロー0・レイアウト不変を Playwright 実測で確認。

## 予防ルール

1. **可読性の床**: 読ませる日本語テキストは 本文系14px以上 / メタ・補助・注記12px以上。
   11px以下が許されるのは装飾英字（SCROLL・FREE等のあしらい）とフォールバック表示のみ
2. **デザイン移植時は床を検品項目に**: 「原本に忠実」より床が優先。移植完了時に
   `grep -o "font-size:[0-9.]*px" | sort | uniq -c` で分布を出し、12px未満の各箇所に
   「装飾か・読ませる文字か」を判定する
3. 同種の人間FBが2回来たら、箇所の修正でなく**規約化**して横展開する（今回の教訓そのもの）
