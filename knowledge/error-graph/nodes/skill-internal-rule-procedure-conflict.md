## 1. Plan / Context
pullie designer は SKILL.md（LOCKED原則 + EDITABLE画風ルール/手順）を注入されて
図解・アイキャッチのプロンプトを組む。画風ルール（2026-08-03人間FB）は
「無機質な箱と矢印だけの図は禁止・人物と場面が見えるシーン型で」と定めていた。

## 2. Do / The Error
2026-08-28〜30、視覚検閲failが集中（監査指摘: 同一文言の画風違反が2日で5件、
アイキャッチは試行1・2とも不合格が2記事連続）:
- 手順2が「**抽象図解（フロー図・ビフォーアフター図）のプロンプトを組む**」と指示しており、
  実際のfailプロンプトは「flow diagram, 3 nodes connected by arrows」— 禁止パターンを
  手順が正面から指示していた
- アイキャッチは手順1「文字入れはしない」に従い無ラベルで生成→検閲は「ラベルが一切なく
  3秒で主題が伝わらない」でfail — ルール間の板挟み
- 検閲→revised_prompt→再生成のループは機能していたが、**初回プロンプトの生成規則が
  矛盾している限り毎記事で同じ往復が発生**（1件あたり生成2回+検閲2回のコスト空転）

## 3. Check / Root Cause
1. 画風ルール追加時（8/3）に同一ファイル内の手順を突き合わせなかった。ルールは
   「べからず」を書き、手順は旧語彙（フロー図）のまま — LLMは具体的な手順の指示に従う
2. 検閲基準（3秒理解・ラベル要求）と生成手順（文字入れ禁止）が別々に進化し、
   生成側が構造的に不合格になる注文を受けていた
3. 既知の同族: 2026-08-10「出典タグ禁止ルール vs C06」（別ファイル間の衝突）。今回は
   **同一ファイル内**でも起きた — ルール/手順/検閲基準の3点はセットで整合を見る必要がある

## 4. Act / Prevention Strategy (Fix)
- 手順2を「シーン型フラットイラストのプロンプトを組む」に修正し、画風ルールへ
  フロー→シーンの**翻訳例**（入力→AI要約→書き戻し ⇒ 人物とAIキャラの場面の連なり）と
  実fail例（fig-14のプロンプト）を追記。アイキャッチは「長文禁止・2〜4語の日本語ラベル可」
  に緩和し検閲基準（3秒理解）と整合させた
- **予防ルール**: ①ルール（べからず）を追加したら、同一SKILL内の手順（やり方）と
  下流の検閲基準の両方をgrepで突き合わせ、旧語彙・矛盾指示を同一コミットで更新する
  ②検閲failが「同一文言で複数回」出たら個別の生成ガチャでなく生成規則の矛盾を疑う
  （検閲ループは矛盾した注文を治せない — 空転コストになるだけ）

## 追記（2026-08-30 実弾検証）: 矛盾源は3箇所目（ワーカープロンプト）にもあった
05_generate_imagesのタスク文にも「担当領域: 手順の抽象フロー図（**矢印+アイコン**）」の
記述があり（2026-08-23のskip濫用較正で追加）、SKILL修正だけでは上書きされる状態だった。
3点目も同語彙で修正後、8/29にfailした実題材（AI連携フロー図解+CSVアイキャッチ）で
designer→生成→視覚検閲を実走 — **両方とも試行1でpass**（プロンプトは「NO boxes, NO arrows,
three character groups」のシーン型に変化・人間の実見でも品質確認）。
**教訓の強化**: ルールの突き合わせ対象は「SKILL・手順・検閲基準」に加えて
**ワーカーが組むタスク文**も含む。LLMへの指示文をgrepする時は語彙（「フロー図」等）で
横断検索し、注入されるすべての層を洗う。
