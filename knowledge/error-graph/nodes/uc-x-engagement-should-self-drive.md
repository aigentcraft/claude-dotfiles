# UC: 「交流相手の確認などはいらない。人格を持って自走する組織にして」

## 症状（ユーザー指摘）
X4で交流・開拓に二段階の人間承認（台帳追加→engage_ok昇格）と受信返信の承認プロトコルを実装
したところ、「確認はいらない・自走させろ・通知は有益情報とアイデアと活動報告だけでよい」
「記事承認のところに通知するな（記事じゃない）」と是正された。

## 根本原因
- このプロジェクトのHITL前例（記事承認）を交流レーンにそのまま輸出した。しかし記事は
  「公開物として恒久に残る成果物」、交流は「日々の会話」— 承認の重みが本来違う
- ユーザーの一貫した設計思想はHOOTL（人間は kill switch / KPI / 監査 / 商談のみ）。
  scout-operator（TikTok自律DM）の前例もあり、能動アクションの自律実行は既定の期待だった
- 通知チャンネルの用途混同: 承認チャンネルに「承認不要の情報」を流した

## 修正
- 交流・開拓・応対を自走化（台帳追加も返信送信もエージェント判断）。安全装置は
  承認でなく機械ガードで担保: C系二層検閲（全送信文）・日次レート上限・ブロックリスト・
  engage_okは「人間ブラックリストフラグ」に意味変更
- 通知は ops チャンネルに「活動報告（人格つき日次ダイジェスト）+ 強シグナル・アイデア」のみ

## 予防ルール
**HITLゲートを新設する時は「これは公開成果物の品質ゲートか、日常活動の許可求めか」を区別する。**
後者はこのユーザーの組織では原則自走+事後報告（安全はレート上限と検閲で担保）。
通知は「承認が必要なもの」だけを承認チャンネルへ。情報共有は活動報告に集約する。
