## 1. Plan / Context
pullie noteは週2（木・日）投稿。01_composeは 生成→約束検品（改稿1回あり）→
blocklist→reviewer C系 の多層ゲートだが、**C系failだけは書き直し0回で即
「今週見送り」**だった（C系=コンプラの絶対ルールを尊重した設計意図）。

## 2. Do / The Error
2026-08-30(日)、C01不合格1件（「誰でも数分で確認できます」の無条件断定 — 一文の
表現修正で確実に直るレベル）で日曜スロットが見送りになり、放置すると前回投稿から
8日空く状態になった。発覚は人間の「noteの投稿止まってない？」。

## 3. Check / Root Cause
1. 「C系違反を自動公開しない」（正しい）と「C系failで即断念する」（過剰）を混同。
   絶対ルールが求めるのは**公開させないこと**であり、修正を試みないことではない
2. 記事レーンは差し戻し→再執筆3回があるのにnoteは0回 — 同じ組織の同種ゲートで
   回復経路が非対称なまま個別進化した
3. 週2カデンツでは1スロットの損失が大きい（=半週分）。ゲート設計時に
   「failのコスト=次の機会までの時間」を考慮していなかった

## 4. Act / Prevention Strategy (Fix)
- C系failに「指摘注入→改稿1回→**必ず再検閲**」を追加（再検閲を通らない限り見送り
  — 絶対ルール4は不変）。実走で見送り分を回収（note#8承認依頼まで到達）
- **予防ルール**: ①検閲・ゲートを設計したら「failしたら次の機会はいつか」を問い、
  修正可能なfail（表現・形式）には回復経路（指摘つき改稿→再ゲート）を対にする。
  即断念してよいのは修正不能なfail（材料不足・事実不在）だけ ②同種ゲートを複数レーンに
  持つ時は回復経路の回数を横並びで点検する（記事3回 vs note0回のような非対称を残さない）
