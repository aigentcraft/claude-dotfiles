## ユーザーの指摘（原文）

「lineの読み取り内容の通知がなんて書いてあるかわかんないし、何でもかんでも雑多に通知している。」

同じ日の朝にも「LINE やメールの内容の通知も案件 DB と明らかに関係のないものが混じっている」と指摘されていた（再発）。

## 1. Plan / Context

LINE デスクトップを背景のまま撮り、Claude（画像）で会話一覧を `{name, preview, unread, official}` に読む。
前回より未読が増えた会話のうち `official=false` を #やり取り に 1 件ずつ出していた。

## 2. Do / The Error

- 保存されていた一覧 6 件のうち 4 件が **IQOS・静岡ガス・カナベイ・ヨシースタッヂ**（企業の配信）。画像の読みが公式と見抜けず、全部「個人の新着」として通知された
- 文面は「💬 LINE に新着（IQOS）> 冒頭30字 未読 3 件。LINE を開いて確認してください」。**誰の何の話で、案件と関係あるのか、何をすればよいのか**が無い
- 案件に LINE を紐づけると「この相手に新着があると、案件と結びつけて通知します」と返事していたのに、**巡回側は紐づけを一度も見ていなかった**（約束だけで未実装）
- 紐づけの読み取りが本文中の「土屋様」（本人宛ての呼びかけ）を相手の名前として job#285 に結んでいた

## 3. Check / Root Cause

- 「通知するか」を **LLM の 1 つの真偽（official）だけ** に委ね、外れた時に広告が全部流れる形だった。除外を一段だけ置くと、その一段の誤りがそのまま利用者に届く
- 通知の文面を「見えたものを貼る」で作り、利用者が次に取る行動を書いていなかった

## 4. Act / Fix（`src/core/line.ts` `planLineNotices`・`src/cli/watch.ts` `lineCycle`）

- 知らせるのは **仕事の連絡だけ**: 案件に紐づいた相手 → その案件のスレッド / 紐づいていないが `work=true` かつ非公式 → #やり取り（紐づけ方を添える）/ それ以外 → 件数だけログ
- 文面は「誰から・未読何件・どの案件・一覧に見えた冒頭（読めなければそう書く）・次に何をするか」
- 一覧で切れた名前（…）は前方一致で紐づける。「〇〇様」「〇〇さん」は紐づけの名前にしない
- selftest に 6 件。故障注入（旧来の `!official` だけ）で 2 件 FAIL を確認

## 予防ルール

- **LLM の 1 つの判定で「出す/出さない」を決めない。** 出す側の条件を積極的に（紐づけ済み・仕事と読めた）定義し、どれにも当たらないものは黙る
- 通知の文面は「何が起きたか」だけでなく **「次に何をするか」まで** 書く
- 利用者に「〜します」と返す文言は、実装に対応する経路があるか検索してから出す
