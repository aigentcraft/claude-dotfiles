## 1. Plan / Context
pullie product/01_sales（BOOTH売上の日次収集）は、セッション失効・プロファイル使用中を
「グレーススキップ（warnログのみ・翌run自己回復）」として設計していた。通知ポリシーは
「単発エラーは通知しない・同一ステップ2run連続失敗のみ介入要求」— ただしこの監視は
**rc≠0のステップ失敗**だけを見る。

## 2. Do / The Error
2026-08-26〜27、BOOTHセッション失効を検知（**後日訂正: 実際はCDP 9222乗っ取りによる
偽ブラウザへの接続が原因の誤検知 — [[cdp-port-9222-hijacked-by-wsl-relay-wrong-browser]]**）。
収集はwarn+rc=0でスキップされ続け、人間には何も届かないまま2日間滞留した。発覚は
人間のログ確認。誤検知ではあったが「本物の失効なら無人復旧は構造的に不可能
（pullie.automateはパスキーオンリー・資格情報不記録方針）」であり、
「翌run自己回復」の前提が成り立たない失敗モードは実在する。

## 3. Check / Root Cause
1. グレーススキップの設計時に、失敗原因を「自己回復するもの（プロファイルロック等の
   一時要因）」と「人間しか直せないもの（セッション失効）」に分類しなかった
2. warn+rc=0 は失敗監視（rc≠0×2run）に信号が届かない — 沈黙死の既知パターン
   （[[x-api-quote-restriction-silent-lane-death]]・[[rotation-starvation-by-unengageable-accounts]]）
   の3例目。個別修理を重ねても、新設レーンが同じ穴を再生産している

## 4. Act / Prevention Strategy (Fix)
- 修正: `booth.session_expired`/`booth.session_ok` イベントで失効連続日数を数え、
  **2日連続で人間へDiscord通知（復旧手順つき）・以後3日ごとに再督促**。単発は従来どおり
  通知しない（誤検知・一時要因はスパムにしない）
- **予防ルール**: グレーススキップ（warn+continue/rc=0）を新設する時は必ず
  「この原因は放置で自己回復するか？」を問い、**人間しか直せない原因が含まれるなら
  継続検知→通知の昇格経路をセットで実装する**（グレーススキップ単体の新設を禁止）。
  昇格の閾値は通知ポリシーに合わせ「2回/2日連続」を既定とする
