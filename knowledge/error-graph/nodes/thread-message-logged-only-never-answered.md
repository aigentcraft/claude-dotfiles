## ユーザーの指摘（原文）

「ディスコード上にメッセージ送ったけどなにも返ってこない。常駐していないのではないか。」

## 1. Plan / Context

案件のスレッド（案件ボードの投稿）に、本人が短い指示を書いた:
「再度やって」（#236・応募内容の作成が時間切れ）/「私の方で応募操作しました」（#77）/「もう一度やって」（#64）。

## 2. Do / The Error

常駐は動いていた（18:53 起動・巡回も送信も正常）。3 件ともログに「スレッド発言を受信」と記録されたが、
**何もせず、スレッドにも何も返さなかった**。本人から見ると常駐が落ちているのと区別が付かない。

## 3. Check / Root Cause

- `onThreadMessage` は、こちらから質問した時の返事（人物像・情報待ち）しか扱わず、それ以外はログに残すだけだった
- **前日のノード（info-request-...）の予防ルール 3「スレッドへの返信をログに残すだけにしない」を書いたのに、コードに入れていなかった**。
  直したのは質問への返事の経路だけで、同じ受け口の残り（自由な書き込み）を放置した
- 黙ることは「動いていない」と同じに見える。人が書いたものに対する無反応は、障害と区別できない

## 4. Act / Prevention Strategy (Fix)

`core/thread-command.ts`（純関数）と `watch.handleJobThreadMessage`:
- 案件のスレッドの短い指示（30 字以内・疑問符なし）を読む: もう一度やって → 作り直し / 応募しました → 応募中 / 見送る → 見送り
- 読めない書き込みには使える言葉を返す。やり取りのスレッドでも「文章からは操作しない。返信案は［非承認］から」と返す
- 前回がファイル添付で止まった案件は、やり直さずに理由を返す（必ず同じところで止まり費用だけかかる）
- 取り消せない操作（応募の実行・送信）はこの経路から呼ばない。本人以外の書き込みには反応しない
- selftest 8 件（実際に書かれた 3 つの言葉を固定）。故障注入 2 種で FAIL を確認

### 予防ルール

1. **人が書いたものには、必ず何か返す。** できないなら「できない・代わりに何をするか」を返す。無反応は障害に見える
2. 予防ルールを書いたら、**その場でコードか検査に落とす**。書いただけのルールは翌日破られる（今回がまさにそれ）
3. 自由文から操作を起こす時は、取り違えても困らない操作に限り、短い文だけを指示とみなす
