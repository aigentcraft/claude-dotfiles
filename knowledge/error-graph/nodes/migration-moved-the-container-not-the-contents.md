## 1. Plan / Context
Discord の案件表示を、チャンネル移動方式からフォーラム（1案件=1投稿）へ移行した。
既存 61 件を DB から作り直し、状態遷移の履歴もタイムラインとして再構築した。
移行自体は「成功 61 / 失敗 0」で完了した。

## 2. Do / The Error
利用者から即座に指摘: **「案件ボード開いたら見送るのボタンしかないのはなんで？」**

検討中の案件から、応募を承認する手段が消えていた。

## 3. Check / Root Cause
1 案件の操作は **2 つのメッセージに分かれていた**。

```
カード（投稿の先頭）  … 状態・条件・［見送る］
応募文メッセージ      … 文面・［承認して応募する］［修正指示］
```

移行スクリプトはカードだけを作り直し、応募文メッセージを運ばなかった。
DB には応募文が残っていた（検討中 12 件すべてに保存済み）ので情報は失われていないが、
**画面上に出ていないものは操作できない**。

見落とした理由は、「案件カード = その案件の UI」と思い込んでいたこと。
実際にはカードは表示の一部でしかなく、**不可逆操作のボタンは別メッセージに載っていた**。
移行前の画面を確認していれば分かったが、DB 起点で作り直したため気づかなかった。

## 4. Act / Fix & Prevention

一度きりのスクリプトで埋めると同じ穴が残るため、整合コマンド（`repair`）の仕事にした。
`repair` は「投稿の有無・タグの一致・**応募文の掲示**」を揃える役割になり、
既に掲示済みかは承認ボタンの customId の有無で判定する（二重掲示を避けるため）。

### 予防ルール

1. **移行の完了条件を「件数」ではなく「操作できること」で定義する。**
   「61 件成功」は器の数であって、機能の回復ではなかった。
2. **移行前に、その画面でできた操作を列挙しておく。**
   移行後に同じ操作がすべて可能かを突き合わせる。DB 起点で作り直すと、
   DB に無い「画面上の要素」（ボタン・添付・リプライ関係）が抜け落ちる。
3. **一度きりのスクリプトで埋めない。** 整合コマンドに寄せると、
   次に同種のズレが起きた時も同じ経路で直せる。
