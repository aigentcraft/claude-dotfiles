## 症状
Google 広告のキーワード検索数 API（Keyword Planner）の「Basic access」を 8/30 に申請し、
CLAUDE.md に「審査待ち（数時間〜）」と書いた。以後 **毎日の定時収集が 403 を返し続け**、
私はそれを「まだ審査中」と読んで 2 週間待った。企画の採点は「需要不明」のまま頭打ちになり、
9/13 には残る企画がすべて skip され記事生産が 0 本/日になった。

## 実際に何が起きていたか
人間の「自分で確認してきて」で Google 広告の API センターを開いたら:
> 「開発者トークンは不要になりました。API アクセスレベルは **Google Cloud コンソールでのみ管理される**ようになりました。
>  このページに表示されているレベルは正確でない可能性があり、このページからアップグレードすることはできません。」

**8/30 に出した申請は、新しい仕組みに引き継がれていなかった。** Cloud コンソールの正しい場所で申請し直したら
**数分で承認**された。さらに承認後も 403 が続き、理由コードを読んだら `CUSTOMER_NOT_ENABLED`
（対象に指定していたクライアントアカウントが有効化されていない。8/30 時点で分かっていた別の問題）。
対象を MCC に変えたら通った。

つまり待っていた 2 週間のうち、**審査に必要だった時間は約 5 分**で、残りは「正しい場所を見ていない」時間だった。

## 根本原因
1. **外部の待ち状態を、再確認の期限なしで記録した。** 「審査待ち」と書いた瞬間に、それは私にとって
   「何もしなくてよい状態」になった。相手の手続きが変わる可能性を織り込んでいない
2. **同じエラーが毎日出ていることを「まだ」と読んだ。** 403 は 14 日間まったく同じ文言だった。
   同一の失敗が 3 日続いたら、それは「待ち」ではなく「調べる」の合図（[[uc-endless-whack-a-mole]] の
   「同文の警告を毎日再送して処理の代わりにする」と同じ型）
3. **エラーの理由コードを最後まで読んでいなかった。** `PERMISSION_DENIED` の `details` に
   `CUSTOMER_NOT_ENABLED` と書いてあった。ログは先頭 200 文字で切っていた

## 修正
- Cloud コンソールの `google/ads-apis/overview` で申請 → 基本アクセス承認
- `.env` の対象アカウントをクライアント（未有効化）から MCC へ
- 取得処理に 429 の待機再試行を追加（バッチ間隔 0.2 → 1.0 秒）
- 全 102 キーワードの検索数を取得（データあり 43）

## 予防ルール
1. **外部の待ちを記録するときは、必ず「再確認する日」と「確認する場所（URL）」を一緒に書く。**
   「審査待ち」だけを書かない。期限を過ぎたら、待つのではなく相手の画面を開く
2. **同一のエラーが 3 日続いたら「待ち」から「調査」に切り替える。** 成果チェックに
   「同じ外部エラーが N 日連続」を赤として足す候補
3. **エラーは理由コードまで読む。** ログの切り詰めは原因を隠す。外部 API のエラーは `details` の
   `errorCode` を必ず記録する
