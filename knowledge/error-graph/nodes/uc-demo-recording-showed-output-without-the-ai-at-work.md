## 1. Plan / Context
ポートフォリオ資料（モーショングラフィックス）のために、Slack に常駐する「AI監督」のデモを画面録画する。
Slack の現場チャンネルを画面いっぱいに広げ、おまかせ再生（職長役の自動投稿）を流して撮る段取りにしていた。

## 2. Do / The Error
人間の指摘「AI監督はAIオフィスと並べて映さないとインパクト薄いよ」。
このデモは、セミナー本番で「Slack（結果）」と「AI建設オフィス（ドット絵のAI社員が分担して働く裏側）」を並べて映す前提で作られていた。
AI監督の行動指針（B工業_AI現場フォルダ/CLAUDE.md §10）にも、オフィスへ逐一報告すると書いてあった。それを読まずに、Slack だけの構図を組んでいた。

## 3. Check / Root Cause
- 撮影の準備で、起動・再生・リセットの手順書（.command）は読んだが、**そのデモが本番でどう見せられていたか**（台本・行動指針・映写の構成）を確認しなかった
- 「結果が出る画面」だけを撮れば足りると考えていた。AI のデモで価値が伝わるのは、**入力 → AI が裏で動く → 結果** が同時に見えるときである

## 4. Act / Prevention
- デモを録画・再現する前に、そのデモの「見せ方の資料」（トークスクリプト、行動指針の映写の節、当日のスライド）を読み、本番の画面構成を再現する
- AI のデモは「原因（人の入力）」と「AI の内部の動き（担当・進み具合）」と「結果」を同じ画面に並べる。1画面で撮れる結果だけでは、AIの仕事ぶりが伝わらない
