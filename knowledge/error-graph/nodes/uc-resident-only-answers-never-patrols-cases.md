## ユーザーの指摘（原文）

「ビズリンクの案件管理で、メールで日程調整の依頼が来ているのに案件に紐づけて通知できていないのはなんで？」
「予約済みでスケジュールにも登録してあるから、そういうのも言われなくてもやるようにLLMを常駐させてるんだからやって。
秘書のスレッドだけ管理すればいいんじゃないからね、このチャンネル全体を統括管理させるんだから。」

## 1. Plan / Context

常駐の Claude Code（秘書）は #🗂秘書 と案件スレッドへの**本人の書き込み**を受けて動く。
定期の片付け（`cli/secretary.ts`）は規則（コード）だけで、LLM が案件を見回ることはない。
メールは届いた時点で「企業名が合う進行中の案件」か「案件の投稿を持つ会話」にだけ紐づける。

## 2. Do / The Error（2026-10-05 の実測）

- ビズリンクはインディードで**手で応募**した求人。案件として登録されず、会話の記録だけがあった
- 9/24「面談の日程調整のお願い」・9/30「ご面談のご案内」のメールは、案件が無いので案件の外（#📌対応事項）へ。
  連絡先（akari.komada@bizlink.io）も案件番号なしで登録
- 10/03 の段階フォーラムへの移行で会話から案件 #361 ができ、やることは移ったが、
  **連絡先・メールの通知・経過は後から拾い直されなかった**
- 本人は面談を予約しカレンダーにも入れていたが、#361 には「面談可能日を確認」「面談を予約する」が開いたまま。
  投稿名は「メッセージ（インディード）」、9/23 時点の古い返信案が承認待ちで残り、段階は応募前のまま（実際は応募済み）

## 3. Check / Root Cause

- **常駐 LLM の担当範囲が「話しかけられたスレッド」だった。** 案件を自分から見回り、メール・カレンダー・会話と突き合わせて
  状態を直す役が誰にも無い。規則の片付けは「古いもの」を流すだけで、「済んだこと」を見つけられない
- **紐づけがその時点の案件の有無だけで決まる。** 後から案件ができた時に、過去の連絡先・メールを引き取る経路が無い

## 4. Act / Prevention Strategy (Fix)

2026-10-05（fukugyo-hootl）: 後から案件ができた時に、紐づいていない連絡先と案件の外に出たメールを引き取る。
常駐の秘書に毎日の見回り（全案件をメール・カレンダー・会話と突き合わせ、済んだやることを閉じ、段階・投稿名・連絡先を直す）を持たせる。

### 予防ルール

1. **常駐させた LLM の担当範囲は「呼ばれたスレッド」ではなく「管理対象の全体」。** 定期に見回る仕事を必ず持たせる
2. **見回りは証拠と突き合わせる。** カレンダーに予定がある・予約確認のメールがある → 日程のやることは済み、のように根拠を添えて閉じ、何をしたかを報告する
3. **紐づけは後からでも追いつかせる。** 案件ができた・名前が分かった時点で、宙に浮いた連絡先・通知を引き取る
